# 검증 기록 — 2026-11-25 (KST)

## 자동 검증

확인한 항목: 50종/등급별 10종, NFKC 이름과 동시 이름 선점, 서버 비밀 세션·초기 지급 1회·쿠키 연장, 외부 Origin/비인증/과대 요청 거절, 모든 낚싯대·미끼·장소 확률 합계와 금지 별 0, 충돌/다리/물가, 낚시 commandId 재전송과 미끼 1회 차감, 미공개 결과 비노출, 오프라인 완료·중복 Alarm 멱등, 완료 예정 시각/생성 순서 순위, 같은 별 재획득/판매 후 기록 유지, 중복 판매/잠금/초과 구매/상점 범위, 동시 방해 1회 성공·즉시 취소·미끼 미반환·미지급, 기한 후 방해 충전 미소모, 오프라인 회복과 기존 회복 타이머 유지, 오프라인 의자 예약, 무료 보충 원자성, Hibernation 소켓 attachment·동일 계정 새 접속, 소켓 세션 만료, 500개 화면 범위를 넘는 잠금 제외 전체 판매.

## 실제 브라우저

별도 Playwright 브라우저 세션 fish-a/fish-b로 낚시남(남)과 낚시녀(여)를 생성했다. 같은 공개 월드에서 서로를 보고 방향키 이동을 확인했다. 1280×720과 1920×1080을 캡처하고 확인했다. 화면 실행에서 발견된 초기 Phaser 생성 순서 오류는 수정 후 다시 실행했다.

첫 낚시에서 피해자 미끼 20→19, 공격자 충전 3→2, 포획/순위 미지급을 확인했다. 이후 새 낚시와 Space 길게 누르기에서 미끼는 19→18로 1개만 소비되고 한 마리만 획득했다. 두 화면의 포획 피드와 순위가 갱신됐다. 상점까지 키보드로 이동해 붕어를 판매한 뒤 코인 100→120, 보유 물고기 0, 최고 기록/순위 유지 확인. 지렁이 10개 구매 후 코인 120→90, 미끼 18→28 확인.

Vite 5173 개발 프록시는 실제 HTTP 계정 생성 200과 WebSocket 연결 성공을 확인했다. 외부 Origin은 개발 프록시를 거쳐도 403으로 거절됐다. 초기 접속의 /api/session 401은 정상 비회원 분기이며, 수정 후 런타임 JavaScript 예외는 없었다.

캡처는 로컬 output/playwright에 저장한다. 원본/기준/합본 검수는 art/references에 보존한다. output은 Git에 포함하지 않는다.

## 동시 접속

분리된 로컬 workerd에 실제 WebSocket 50개를 연결해 30초 동안 동시 이동했다. 14,800 이동 입력, 메시지 오류 0, 종료 시 연결 50개 유지, 51번째 접속 HTTP 503. ping 중앙값 18ms / 95백분위 98ms. 원본은 docs/load-test.json이다.

최초 시도는 개발 서버 코드 갱신으로 소켓이 닫혀 유효한 지속 접속 결과로 사용하지 않았다. 이후 개발 파일 감시의 영향을 받지 않는 별도 번들/데이터 서버에서 위 결과를 얻었다. 동일 PC의 짧은 프로토콜 부하 검증이며, 50개 브라우저의 렌더링이나 운영 엣지·실사용 인터넷·장시간 비용/안정성 검증을 뜻하지 않는다.

## 배포와 남은 범위

Wrangler deploy --dry-run으로 Worker/정적 자산/SQLite DO 바인딩 패키징을 검사했다. 이후 사용자가 GitHub kimkyutack/fishhook-game의 main과 Cloudflare fishhook-game Worker를 연결했다. 최초 빌드 #0d1908d2는 시뮬레이션 가격 변수의 TS2322 오류로 실패했으며, number 타입을 명시해 수정했다. 로컬 빌드/테스트 통과와 원격 CI 성공은 구분하며, 수정 커밋의 실제 결과는 Workers Builds 대시보드에서 확인한다. 장시간/여러 지역의 운영 검증과 Cloudflare 엣지의 실제 Hibernation eviction 비용 측정은 남아 있다.

가방은 최근 보유 500개를 표시하며, 잠금 제외 전체 판매는 서버의 전체 보유 물고기에 적용된다. PC 키보드 우선이며 모바일 터치 이동과 효과음은 없다. 초기 밸런스는 docs/economy.md의 기대값과 2,000회씩의 시뮬레이션으로 확인했으며 사람의 장시간 플레이테스트는 수행하지 않았다.
