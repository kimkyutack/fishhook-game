# 발차기

- Space는 발차기 전용이며 상대가 없으면 허공 발차기를 합니다. 앉기는 C로만 실행합니다. 우측 하단 발차기 버튼도 같은 명령을 전송합니다. 충전·횟수 제한과 기존 60초 보호는 사용하지 않습니다.
- 앞쪽 150도, 월드 거리 180 이내(화면 줌에 따라 보이는 길이는 다름)이고 장애물에 가리지 않은 상대에게 사용할 수 있습니다. 공격자의 기존 발차기·도주 동작은 유지합니다.
- 낚시 중인 상대는 기존 낚싯대 놓침 모션을 사용합니다. 낚시는 즉시 취소하며 사용 미끼와 예정 물고기는 지급하지 않습니다. 다시 F를 눌러야 낚시합니다.
- 서 있거나 앉아 있는 상대는 `fallen` 상태로 넘어지고 의자·낚싯대는 표시하지 않습니다.
- 피격 후 1,500ms 동안 서버가 이동과 게임 명령을 거부합니다. 일반 넘어짐은 그 뒤 350ms 동안 일어나며, 행동을 입력하면 즉시 이어집니다. 일어나는 중에는 다시 맞지 않습니다.
- 상태 시작 시간과 8방향을 SQLite와 WebSocket attachment에 저장하여 새로고침해도 제한을 초기화하지 않습니다.
- 접속을 유지하지 않는 캐릭터는 기존 규칙대로 낚시 중일 때만 맵에 남습니다.

## 이미지

내장 `image_gen`으로 남녀 각각 기본 방향과 대각 방향 원본 2장씩 제작했습니다. 투명 배경을 검수한 4장 원본을 보관하고, 각 캐릭터 8방향 × 6포즈를 192px 프레임으로 등록했습니다. 왼쪽과 왼쪽 대각선은 해당 오른쪽 시점의 좌우 반전으로 방향을 맞춥니다. 단순히 서 있는 이미지를 회전시키는 방식이 아닙니다.

- 원본: `art/source/{male,female}-fall-{cardinal,diagonal}.png`
- 게임 이미지: `public/assets/redesign/{male,female}_fall.png` (1152×1536, 48프레임씩)
- 생성 프롬프트: `art/prompts/kick-fall.json`
- 등록·해시·방향: `art/kick-manifest.json`
- 다시 패킹: `node --import tsx scripts/pack-fall-assets.ts`
- 검증: `npm run check`, `npm test`, `npm run assets:check`

기존 데이터의 `sabotage_state` 및 충전 API 필드는 이전 버전 호환을 위해 보존하지만 발차기 사용 판정과 UI에는 사용하지 않습니다. 이전 열린 클라이언트의 `sabotage` 명령도 동일한 무제한 발차기로 처리합니다.

## 검증 (2026-11-26)

- Cloudflare Vitest 통합 테스트 43개 통과. 충전 0과 기존 보호 시각이 있어도 8방향의 서 있는/앉은 상대에게 성공합니다.
- 1,499ms의 이동·게임 명령은 거부하고 1,500ms부터 허용합니다. WebSocket을 끊은 뒤 다시 연결해도 넘어짐 상태·방향·시작 시간이 유지됩니다.
- 기존 낚시 취소의 미끼 미반환·물고기 미지급·동시 취소 한 번 성공도 통과합니다.
- 자산 검사: 2개 아틀라스, 96개 프레임의 해시·투명 여백·잘림·빈 프레임 검사 통과.
- 별도 로컬 Worker(8796, 임시 SQLite)와 Chrome의 독립 세션 2개(127.0.0.1 / localhost)에서 실제 발차기를 확인했습니다. 서 있는 상대/앉아 있는 상대 모두 넘어지며, 의자가 사라지고 자동으로 일어납니다. 브라우저 오류 로그 없음.
- 화면 증거: `art/references/kick-seated-browser.jpg`, `art/references/kick-recovered-browser.jpg`.
- 프로덕션 배포는 이 작업에서 실행하지 않았습니다.

## 스페이스 전용 입력과 사거리 수정 (2026-11-26)

- Space가 주변 행동의 앉기/상점/낚시로 넘어가던 연결을 제거했다. C는 앉기, F는 낚시/상점, Space는 발차기만 실행한다. 상대가 없으면 서버에서 500ms 허공 발차기를 확정하고 다시 선다.
- 사거리 96→180, 실제 8방향 시선을 기준으로 앞쪽 150도를 판정한다. 장애물을 통과하는 타격과 뒤쪽 타격은 막고, 겹친 좌표에서는 0으로 나누지 않는다. 서버가 가장 가까운 유효 대상을 선택한다.
- 키보드와 퀵슬롯은 같은 함수를 호출한다. 발차기 애니메이션 방향은 표시 중인 시선에 맞춘다. 명령 결과의 type이 ack를 덮던 문제를 고쳐 재접속 대기 명령이 정상 해제된다.
- 타입 검사/프로덕션 빌드/이미지 검사 및 workerd 테스트49개 통과. 새 검사에는180 경계,181 거절, 뒤쪽 거절, 대각선 시선,160 거리 자동 선택, 허공 발차기, 겹친 좌표, WebSocket ack가 포함된다.
- 운영과 분리한 로컬8797의 Chrome/IAB 두 브라우저에서 직접 Space를 입력했다. 137.98 거리의 서 있는 상대와154.13 거리의 낚시 중 상대가 맞았다. 실제 WebSocket 송신은 kick만 포함하며 sit/cast는 없다. 피해자의 낚시가 즉시 취소되고 미끼19개 유지, 물고기 미지급, 자동 재시작 없음, 양쪽 콘솔 오류0건을 확인했다.
- 증거: output/kick-key-qa/network-proof.json, fishing-network-proof.json, victim-hit.jpg, after-fishing-kick.jpg. 검증용 브라우저는 모두 닫았다. 운영에는 검증 캐릭터를 새로 만들지 않았다.
- 최종 운영 배포71e8e760-631a-4d05-8800-dce61d2a10aa 완료. 운영 index.html과 Game-CZT0-263.js를 내려받아 로컬 빌드와 바이트 일치를 확인했다. CLI 배포이며 Git 커밋/푸시는 하지 않았다. 검증 전용 로컬 서버8797도 종료했다.
