# 외형 상점·애니메이션 검증 (2026-11-27)

- 외형: 오리 유치원생 / 꼬마 회사원 / 꼬마 산타. 남녀 각각 제작, 모두 3,000코인.
- 상점 외형 탭에는 로그인한 캐릭터 성별의 3종만 표시한다. 서버의 계정 성별로 이미지 경로를 선택하며 성별을 변경하는 명령은 없다.
- 가방 외형 탭에는 기본 외형과 구매한 외형만 표시한다. 구매와 장착은 별개이며 기본 외형으로 무료 복귀할 수 있다.
- 서버 SQLite 마이그레이션 5: `players.costume` 기본값 `default`, `player_costumes` 소유권·구매 시각. 기존 계정·잔액·낚시 기록을 유지한다.
- 서버가 가격·상점 거리·잔액·소유권·중복 구매·낚시 중 장착 제한을 검사한다. 구매 요청 재시도는 기존 명령 ID로 중복 차감을 막는다.
- 공개 플레이어 상태와 순위에 외형을 전달한다. 월드 캐릭터·HUD·프로필·미니맵·순위 초상화에 반영한다.

## 이미지

내장 `image_gen`으로 원본 18장(외형 6종 × 이동 / 낚시 / 액션)을 제작했다. 각 원본은 8열 × 5방향의 40프레임이다. 총 720개의 고유 프레임을 잘라 게임용 WebP 아틀라스 6개와 PNG 초상화 6개로 등록했다. 정면·후면·오른쪽·우하향·우상향을 직접 제작하고 왼쪽 3방향은 대칭 반전한다.

- 걷기·달리기·대기·앉기·앉은 대기·던지기·낚시 대기·끌어올리기·발차기·놀람·넘어짐·일어서기 연결.
- 동일 외형의 방향마다 고정된 배율, 머리 중심과 발 기준점(192px 프레임, 발 y=180)을 사용한다.
- 의자·낚싯대는 기존 장비 이미지를 별도 레이어로 합성한다.
- 원본: `art/source/costumes/`, 프롬프트: `art/prompts/costume-assets.json`, 등록 정보·해시: `art/costume-manifest.json`, 실제 배포 이미지: `public/assets/costumes/`.
- 원본을 다시 생성하지 않고 `npm run assets:pack:costumes`로 등록 파일을 재생성할 수 있다.

## 검증 결과

- `npm run build`: 통과.
- `npm test`: 10개 파일, 72개 테스트 통과. 신규 6개는 기존 계정 스키마 변경 후 잔액·이름·장비 유지, 남녀 전 외형 가격·구매·장착·재초기화 후 영속성·중복 차감 방지·위조 값·잔액·거리·낚시 중 장착 제한을 검사한다.
- `npm run assets:check`: 기존 자산 및 외형 720프레임의 비어 있음·프레임 가장자리 잘림·크기·해시·8방향 모션 참조 검사 통과.
- Chrome 남자 / 인앱 브라우저 여자 계정에서 외형 3종을 실제 구매·장착했다. 각 10,000 → 1,000코인, 성별에 맞는 초상화만 표시됨. 버튼 이미지·색상·가로세로 중앙 정렬 확인.
- 두 화면의 미니맵에 상대의 변경된 외형이 실시간 반영됨. 재접속 후 소유·장착·잔액 유지, 기본 외형 복귀와 재장착 확인.
- 장애물이 없는 위치에서 8방향 이동 확인. 상점 옆 장애물에 막히는 이동과 미니맵 갱신 시차는 분리하여 재확인했다.
- 추가 로컬 두 세션에서 여자 회사원 낚시를 남자 오리 캐릭터의 발차기로 취소했다. DB 상태 `CANCELLED_BY_SABOTAGE`, ACTIVE 0개, 미끼 19 → 18, 인벤토리 1개 유지. 이후 자동 재시작 없음.
- 서 있는 캐릭터도 발차기하여 `fallen` 상태, 바닥에 누운 프레임, 일어서기, 수동 낚시 재개 가능 상태를 확인했다. 브라우저 런타임 오류 없음.
- 화면 증거: `output/costume-qa/` (검증용 산출물, Git 제외). 운영 계정·재화·캐릭터는 변경하지 않았다.
