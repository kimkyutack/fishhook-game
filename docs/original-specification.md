# Codex 실행 프롬프트 — 이미지 기반 실시간 웹 낚시 게임

아래 명세에 따라 현재 저장소에 실제로 실행 가능한 웹 낚시 게임을 구현하라. 임시 프로젝트명은 “물가마을”이다. 설계나 화면 시안만 제시하고 끝내지 말고, 클라이언트·서버·게임 데이터·이미지 연결·검증·Cloudflare 배포 설정까지 구현하라.

현재 저장소의 AGENTS.md와 기존 코드, 사용 가능한 도구부터 확인하라. 기존 프로젝트가 있으면 그 구조를 존중하고, 비어 있으면 아래 기술 구성으로 시작하라. 일상적인 구현 선택은 이 명세를 기준으로 진행하고, 반드시 필요한 권한이나 자료가 없는 경우에만 정확한 부족 항목을 알려라.

여기에 제시한 가격·확률·시간·동시 접속 인원은 초기 구현을 위한 제안값이다. 실제 플레이 테스트로 검증된 수치라고 설명하지 말고, 한곳에서 변경 가능한 설정으로 분리하라.

## 1. 게임의 목표와 핵심 경험

여러 사람이 같은 맵을 걸어 다니며 연못·강·호수에서 낚시하고, 잡은 물고기를 자랑하고, 판매한 코인으로 장비와 미끼를 마련하는 캐주얼 소셜 게임이다.

반드시 구현할 흐름:

1. 처음 방문하면 이름 입력.
2. 이름을 입력한 뒤 남자·여자 캐릭터 중 하나 선택.
3. 게임 시작을 누르면 바로 같은 공개 월드에 입장.
4. 방향키로 이동하고 원하는 땅에 의자를 놓고 앉기.
5. 미끼가 있는 상태에서 물가에 접근하면 “낚시” 버튼 표시.
6. 버튼 클릭 또는 Space로 낚시 시작.
7. 서버가 정한 시간이 지나면 물고기를 획득하고 주변 사람에게 보여 주기.
8. 중앙 상점에서 물고기를 팔고 미끼·낚싯대를 구매.
9. 높은 등급의 물고기를 더 먼저 잡아 좌측 순위에 오르기.
10. 낚시 중인 다른 사람에게 다가가 낚싯대를 발로 차는 장난을 하고 달아나기.

실제 멀티플레이어 상태와 영속 데이터를 구현한다. 다른 사용자를 가짜 NPC로 대체하거나, localStorage만으로 재화와 순위를 저장한 상태를 완성품으로 제출하지 않는다.

## 2. 기술 구성과 범위

기본 기술 구성:

- 클라이언트: React + TypeScript + Vite.
- 월드 렌더링: Phaser의 작업 시작 시점 안정 버전. 공식 문서에 맞는 API 사용.
- UI: React 오버레이. 게임 엔진과 UI의 상태 연결을 명확히 분리.
- 서버: Cloudflare Workers.
- 실시간 통신: Durable Objects의 WebSocket Hibernation API.
- 영속 데이터: SQLite 기반 GameWorldDO의 내장 저장소.
- 배포: Workers Static Assets + Workers Builds의 Git 연결.
- 이미지: 투명 PNG/WebP, 스프라이트 아틀라스, 분리된 환경 레이어.
- 유료 Workers 환경을 전제로 하되 무제한 사용량이나 고정 비용을 보장하지 않는다.

처음에는 `world-v1`이라는 공개 월드 하나를 구현한다. 같은 주소로 접속한 모든 플레이어는 이 월드에서 만난다. 초기 동시 접속 목표는 50명이며, 최대 인원 설정과 만원 안내를 구현하고 실제 부하 검증 결과를 기록한다. 이 숫자는 Cloudflare의 보장 성능이 아니다.

사용자·세션·재화·낚시·아이템·랭킹은 모두 동일한 GameWorldDO의 SQLite를 권위 있는 원본으로 사용한다. D1과 DO에 같은 코인 정보를 각각 저장하지 않는다. 여러 월드로의 확장은 후속 설계로 남기고 이번 단일 월드가 무제한으로 확장된다고 설명하지 않는다.

최적화한 런타임 이미지는 Static Assets로 함께 배포한다. R2는 대형 원본이나 추가 이미지 제공이 실제로 필요할 때 확장할 수 있게 에셋 경로 설정만 분리한다. 처음부터 불필요한 데이터베이스와 스토리지 의존성을 추가하지 않는다.

## 3. 이름, 캐릭터 선택, 자동 로그인

별도 이메일·비밀번호 가입 화면 없이 비회원 게스트 계정을 사용한다. 이름은 공개 표시명이고, 계정 소유권은 서버가 발급하는 비밀 세션으로 확인한다.

- 이름은 Unicode NFKC 정규화와 앞뒤 공백 제거 후 2~12자로 제한.
- 허용 문자는 한글·영문·숫자·밑줄. 공백과 제어 문자, 보이지 않는 문자는 거절.
- 영문 대소문자를 무시한 정규화 키에 UNIQUE 제약을 둔다.
- 입력 단계의 중복 확인과 별개로, 최종 시작 요청에서 이름 선점·캐릭터 생성·시작 물품 지급·세션 생성을 원자적으로 처리한다.
- 이미 사용 중인 이름을 입력했다는 이유만으로 해당 계정에 로그인시키지 않는다.
- 남녀 캐릭터는 외형만 다르고 능력치는 같다.
- 유효한 세션이 있으면 이름 입력과 캐릭터 선택을 건너뛰고 기존 플레이어로 복귀한다.
- 서버가 충분히 긴 암호학적 난수 세션 토큰을 발급하고 토큰 해시·플레이어 ID·만료 시각을 저장한다.
- 운영 환경 쿠키는 `HttpOnly; Secure; SameSite=Lax; Path=/`로 설정한다.
- 브라우저를 다시 열어도 복귀할 수 있도록 초기 유효기간은 30일로 설정하고, 유효 세션의 활동에 따라 서버 만료와 쿠키를 함께 연장한다.
- 세션 연장은 동일 출처 HTTP 응답의 Set-Cookie로 처리한다. WebSocket 메시지만으로 서버 만료만 연장하고 브라우저 쿠키를 갱신하지 않는 불일치를 만들지 않는다.
- sessionStorage에 이름만 넣어 인증을 처리하지 않는다. localStorage는 음량 같은 비민감 설정에만 사용한다.
- 세션 토큰을 WebSocket URL이나 로그에 노출하지 않는다.
- 동일 계정의 동시 플레이는 활성 연결 하나로 제한한다. 새 연결을 사용할 때 이전 연결은 종료하고 이전 화면의 자동 재연결도 중지한다.
- 쿠키 삭제·만료 또는 다른 기기에서는 이름만으로 기존 계정을 복구할 수 없다는 점을 README와 설정 화면의 짧은 계정 안내에 명시한다.

시작 지급:

| 항목 | 지급량 |
|---|---:|
| 코인 | 100 |
| 기본 낚싯대 | 1개 |
| 접이식 의자 | 1개 |
| 지렁이 미끼 | 20개 |
| 방해 충전 | 3개 |

최초 지급은 계정 생성 때 한 번만 수행한다. 새로고침·재접속·재전송으로 다시 지급되지 않아야 한다.

## 4. 맵, 카메라, 화면 구성

### 맵

- 고정 정사영의 3/4 탑다운 시점으로 만든다. 화면 기준 상하좌우 이동이 자연스럽게 보여야 한다.
- 이미지에 원근과 부피감을 그려 2.5D를 표현한다.
- 기본 맵 크기는 약 3072×2048 월드 픽셀로 시작하고, 캐릭터 표시 높이는 약 80~96픽셀로 조절한다.
- 중앙: 상점 NPC와 작은 낚시용품 가판대, 넓은 광장.
- 서쪽: 아담한 연못, 풀과 연꽃, 완만한 물가.
- 북쪽과 동쪽: 흐르는 강, 강변 길, 통행 가능한 다리.
- 남동쪽: 넓은 호수, 갈대와 선착장.
- 모든 낚시 장소가 도보로 연결되어야 한다.
- 연못·강·호수는 각각 전용 어종을 제공한다.
- 물, 나무 몸통, 바위, 상점에는 충돌을 적용한다. 플레이어끼리는 길을 막지 않도록 통과할 수 있게 한다.
- 의자는 물·장애물·NPC·다른 의자와 겹쳐 놓을 수 없다.
- 물가를 따라 낚시 가능한 위치, 수면 도달점, 바라볼 네 방향을 데이터로 정의한다.
- 지점은 충분히 촘촘하게 배치해 자연스럽게 원하는 물가에서 낚시할 수 있게 한다.
- 그림에 보이는 물가와 실제 판정이 일치하도록 충돌·낚시 영역을 디버그 오버레이로 확인한다.

맵을 하나의 거대한 이미지로만 만들지 않는다. 바닥·수면·물가·오브젝트·앞쪽 가림 장식을 분리한다. 캐릭터와 오브젝트는 지면 기준점의 Y값으로 정렬하고, 나무와 건물의 앞뒤 가림이 자연스럽게 작동해야 한다.

### 화면

PC 웹과 키보드 조작을 우선하며 1280×720과 1920×1080에서 검수한다.

- 좌측: 폭 약 220~260픽셀의 순위 패널.
- 중앙과 우측 대부분: 실제 플레이하는 맵.
- 상단: 내 이름, 코인, 장착 낚싯대, 미끼 수량, 방해 충전 아이콘.
- 하단 중앙: 현재 상황에 맞는 행동 버튼 하나와 작은 Space 키 표시.
- 우측 상단 또는 하단: 장비·가방 버튼과 I 키 표시.
- 우측 가장자리: 짧은 최근 포획 피드.
- 작은 화면에서는 순위를 접을 수 있게 하되 맵과 행동 버튼이 잘리지 않게 한다.

계정 입력→캐릭터 선택→게임이 자연스럽게 이어지도록 만들고, 장비 창과 상점은 게임 위에 열리는 창으로 구성한다.

## 5. 조작과 상호작용

| 입력 | 행동 |
|---|---|
| 방향키 | 화면 기준 상하좌우 이동 |
| Space | 화면에 표시된 주요 행동 실행 |
| I | 장비·미끼·보유 물고기 창 열기/닫기 |
| C 또는 의자 버튼 | 유효한 땅에서 앉기/일어서기 |
| Esc | 열린 창 닫기, 창이 없으면 진행 중 낚시 취소 |
| 행동 버튼 클릭 | Space와 동일한 명령 실행 |

- 대각 이동 속도는 정규화하고, 바라보는 방향은 가장 최근 유효 입력 축에 맞춰 네 방향 중 하나로 정한다.
- 입력창이나 모달에 포커스가 있으면 월드 이동과 행동 단축키를 막는다.
- 게임 조작 중에만 방향키와 Space의 브라우저 스크롤을 막는다.
- Space의 키 반복 이벤트를 무시한다. 길게 누른다고 연속 방해나 연속 낚시가 되면 안 된다.
- 포커스를 잃거나 탭이 숨겨지면 이동 입력을 즉시 해제한다.
- 서버의 행동 승인 전에 미끼·코인·충전을 확정적으로 차감하지 않는다.

Space 주요 행동의 우선순위:

1. 모달·입력창·행동 모션 중에는 월드 행동 없음.
2. 본인이 낚시 중이면 새 낚시와 방해 없음.
3. 상점 NPC 가까이에서는 “상점”.
4. 정면 가까이에 방해 가능한 낚시 중인 사용자가 있으면 “방해”.
5. 유효한 물가이고 사용 가능한 미끼가 있으면 “낚시”.

동시에 여러 사람을 방해할 수 있는 상황에서는 정면의 가장 가까운 한 명을 선택한다. 대상에게 작은 이미지 표식을 표시하고, Space가 실행할 행동명과 실제 명령이 일치해야 한다. 위치·방향·상태는 서버에서 다시 검사한다.

초기 상호작용 거리: 물가 64픽셀, 상점 96픽셀, 방해 대상 96픽셀. 실제 캐릭터와 맵 크기를 확인해 설정에서 조절한다. 방해는 장애물을 가로질러 실행되지 않게 한다.

## 6. 의자와 낚시 진행

의자는 기본 지급 장비이며 소모되지 않는다. 걷기 가능한 땅에서 C로 앉을 수 있다. 유효한 물가에서 낚시를 누르면 의자 배치→앉기→던지기를 자동으로 연결한다.

낚시 한 회의 흐름:

`idle/seated → sitting → casting → waiting → reeling → caught → seated`

방향키·C·Esc로 낚시를 취소하면 일어서고 이동 가능한 상태로 돌아온다. UI가 열린 동안 방향키는 낚시 취소에 사용하지 않는다.

서버가 시작을 승인할 때:

1. 위치·장소·방향·의자 자리·낚싯대·미끼·진행 중 낚시를 검증한다.
2. 미끼 1개를 소비한다.
3. 등급과 어종을 추첨한다.
4. 소요 시간을 정한다.
5. 낚시 ID, 장비와 미끼 스냅샷, 결과, 시작·완료 시각을 영속 저장한다.
6. 의자 자리의 위치와 방향도 저장해 연결이 끊겨도 현재 낚시와 방해 판정을 유지한다.

낚싯대의 허용 등급이나 장비 변경으로 진행 중인 결과를 다시 추첨하지 않는다. 미끼가 여러 종류 있으면 사용자가 장착한 종류를 사용하며, 소진됐다고 다른 미끼를 몰래 소비하지 않는다.

| 별 | 시작 승인부터 획득까지의 기본 시간 | 판매가 |
|---|---|---:|
| 1성 | 6~10초 | 20 |
| 2성 | 10~16초 | 60 |
| 3성 | 18~28초 | 160 |
| 4성 | 35~55초 | 550 |
| 5성 | 75~110초 | 2,500 |

같은 별의 어종은 초기 버전에서 같은 판매가를 가진다. 시간은 해당 범위에서 서버가 정한다. 캐스팅은 시작 직후 재생하고, 서버의 포획 확정 이벤트를 받으면 짧은 릴 감기와 획득 연출을 재생한다. 연출이 끝난 시각으로 서버 포획 기록을 늦추지 않는다.

- 별도 타이밍 미니게임 없이 시간이 지나면 자동 획득한다.
- 완료 전에는 소유자를 포함한 클라이언트에 결과 어종·별·총 소요 시간·완료 예정 시각을 보내지 않는다. 공개 스냅샷에는 시작 시각과 현재 행동 상태만 포함한다.
- 정확한 남은 초 대신 찌·물결·캐릭터 반응으로 기다리는 상태를 보여 준다.
- 완료 후 보유 물고기와 도감에 반영하고, 물고기를 보여 주는 짧은 연출 뒤 계속 앉아 있게 한다.
- 1회 입력은 낚시 1회다. 다음 낚시는 다시 눌러야 한다.
- 취소한 낚시의 미끼는 반환하지 않는다.
- 취소 시점에 이미 완료된 낚시는 먼저 완료 처리한다.
- 연결이 끊겨도 이미 승인된 낚시 한 회는 서버에서 완료한다. 오프라인 자동 반복은 하지 않는다.
- 진행 중인 낚시의 캐릭터와 의자는 연결 종료 후에도 완료·취소까지 월드에 남고 방해 대상이 된다. 연결을 끊어 방해를 피할 수 없게 한다.
- 그동안 의자 자리를 예약하고 재접속하면 같은 자리로 복원한다. 완료·취소 후에도 오프라인이면 캐릭터를 정리하고 예약을 해제한다.
- 재접속하면 진행 중인 낚시나 이미 완료된 결과를 복원한다.
- 장비 창을 열어도 서버의 낚시는 계속된다. 진행 중 낚싯대·미끼 변경은 완료 또는 취소 뒤에 적용한다.

## 7. 물고기 50종과 도감

정확히 50종, 등급별 10종을 만든다. 별은 어종의 고정 속성이다. 아래는 게임용 배치이며 실제 생태·희귀도 분류를 뜻하지 않는다. 4~5성은 창작 어종이다.

표의 행 순서, 각 행의 연못→강→호수 순서로 `fish_001`부터 `fish_050`까지 고유 ID를 부여한다.

| 등급 | 연못 | 강 | 호수 |
|---|---|---|---|
| 1성 | 송사리, 참붕어, 납자루, 붕어 | 피라미, 버들치, 모래무지 | 빙어, 살치, 줄몰개 |
| 2성 | 미꾸라지, 동자개, 향어 | 은어, 황어, 쉬리, 꺽지 | 메기, 누치, 동사리 |
| 3성 | 비단잉어, 금붕어, 가물치 | 산천어, 무지개송어, 쏘가리 | 잉어, 철갑상어, 큰입배스, 블루길 |
| 4성 | 연꽃꼬리잉어, 홍옥금붕어, 나뭇잎지느러미어 | 청옥은어, 수정송어, 불꽃지느러미쏘가리 | 백금철갑어, 달빛메기, 유리비늘향어, 별무늬가물치 |
| 5성 | 연화왕잉어, 태양금붕어, 유리날개어 | 청룡장어, 오로라송어, 혜성돛새치 | 황금뿔메기, 달무리철갑어, 운해가오리, 별바다용어 |

각 어종 데이터:

`id, name, star, habitat, sellPrice, imageKey, displayScale, visualDescription`

- 각 장소에서 1~5성이 모두 존재해야 한다.
- 모든 종에 실제 고유 이미지가 있어야 한다.
- 같은 이미지의 색만 바꿔 50종으로 계산하지 않는다.
- 지느러미, 몸통 비율, 꼬리, 수염, 비늘 패턴 등으로 종마다 실루엣을 구별한다.
- 5성은 물고기 자체의 형태가 특별해야 한다. 테두리와 과도한 빛으로만 희귀함을 표현하지 않는다.
- 도감은 50칸이며 미획득은 실루엣, 획득은 원본 이미지와 별을 보여 준다.
- 판매 후에도 도감과 포획 이력은 유지한다.
- 무게나 길이에 따른 추가 랭킹 규칙을 임의로 만들지 않는다.

## 8. 낚싯대와 미끼

### 낚싯대

낚싯대는 총 3단계다. 내구도나 파손은 없다.

| 단계 | 이름 | 구입 비용 | 포획 가능한 별 |
|---|---|---:|---|
| 1단계 | 기본 낚싯대 | 최초 지급 | 1~3성 |
| 2단계 | 숙련 낚싯대 | 2,500코인 | 1~4성 |
| 3단계 | 명인 낚싯대 | 15,000코인 | 1~5성 |

- 3단계 구매에는 2단계 보유가 필요하다.
- 가격은 각 단계의 추가 구입 비용이다.
- 구매한 장비는 영구 보유하고 I 창에서 장착한다.
- 구매 후 즉시 장착할 수 있는 짧은 버튼을 제공한다.
- 1단계로 4·5성, 2단계로 5성은 절대로 잡을 수 없다.
- 좋은 미끼도 낚싯대 제한을 넘지 못한다.
- 단계는 등급 상한만 결정한다. 숨겨진 확률 보너스를 추가하지 않는다.
- 세 낚싯대의 몸체·릴·손잡이 형태와 재질을 이미지로 구별한다.

### 미끼

| 미끼 | 1개 가격 | 구매 조건 | 1성 가중치 | 2성 | 3성 | 4성 | 5성 |
|---|---:|---|---:|---:|---:|---:|---:|
| 지렁이 | 3 | 없음 | 60 | 27 | 10 | 2.8 | 0.2 |
| 배합 미끼 | 15 | 없음 | 25 | 40 | 26 | 8.2 | 0.8 |
| 생미끼 | 50 | 2단계 낚싯대 보유 | 10 | 25 | 40 | 23 | 2 |
| 특별 미끼 | 120 | 3단계 낚싯대 보유 | 5 | 15 | 30 | 44 | 6 |

각 행의 합계는 100이다. 표는 모든 별이 허용됐을 때의 기본 가중치다.

실제 추첨은 반드시 다음 순서로 처리한다.

1. 미끼의 별 가중치를 읽는다.
2. 장착 낚싯대로 불가능한 별을 제거한다.
3. 현재 장소에 어종이 없는 별을 제거한다.
4. 남은 별 가중치를 합계 1로 재정규화한다.
5. 별을 추첨한 뒤, 해당 장소·별의 어종 중 균등 추첨한다.

예: 1단계 낚싯대와 지렁이는 `60:27:10`을 합계 97로 나눈 실효 확률이다. 불가능한 별을 뽑았다가 실패시키거나 가장 낮은 별로 바꾸지 않는다.

미끼 설명은 이름·가격·주요 효과 정도로 짧게 한다. 확률 상세를 열었을 때는 현재 장비와 장소의 실효 확률을 보여 준다. 미끼는 개수 단위로 사고, 1개·10개·선택 수량 구매를 제공한다.

## 9. 상점과 재화

중앙 NPC 가까이에서 상점 버튼이나 Space로 연다. 구매와 판매는 실제 NPC 상호작용 범위에서만 가능하다.

상점은 이미지 중심의 탭 세 개로 구성한다.

- 낚싯대
- 미끼
- 물고기 판매

구현할 기능:

- 잔액, 보유 수량, 장비 구매 조건 표시.
- 물고기 개별 판매와 선택 판매.
- 보관 잠금과 잠금 물고기를 제외한 전체 판매.
- 판매 예정 수량·합계 금액 표시.
- 실제 소유 물고기만 판매 가능.
- 같은 물고기를 중복 판매하지 못하도록 서버 원자 처리.
- 코인과 수량은 정수이며 음수가 될 수 없음.
- 가격과 판매가는 클라이언트 입력을 신뢰하지 않고 서버 카탈로그에서 조회.
- 플레이어 간 아이템·재화 전송은 이번 범위에 넣지 않음.

진행 불가 방지:

보유 미끼가 0이고, 보유 물고기도 0이며, 코인이 지렁이 1개 가격보다 적으면 상점에서 지렁이 3개를 무료로 보충한다. 조건을 서버에서 검사하고 하나의 트랜잭션으로 지급한다. 조건에 맞는 플레이어가 기다리지 않고 다시 낚시할 수 있어야 한다.

## 10. 순위와 최고 기록

순위는 “최고 별을 먼저 잡은 사람” 기준이다.

정렬 키:

1. `bestStar` 내림차순.
2. 해당 별을 처음 잡은 `bestCaughtAt` 오름차순.
3. 시각이 같으면 서버 전역 `bestCatchSequence` 오름차순.

핵심 예:

- A가 5성을 먼저 잡고 B가 나중에 5성을 잡으면 A가 1위.
- B의 물고기가 더 비싸거나 B가 여러 마리를 잡아도 A를 앞서지 못한다.
- 5성이 없는 동안에는 4성을 먼저 잡은 사람이 1위.
- 한 번 더 높은 별을 잡으면 대표 물고기를 그 첫 기록으로 교체.
- 같은 별을 다시 잡아도 대표 물고기와 그 별의 최초 달성 시각은 유지.
- 대표 물고기를 팔아도 순위와 기록은 유지.
- 아직 물고기가 없는 플레이어는 순위 밖.
- 이번 버전에는 시즌 초기화가 없다. 최초 5성의 1위 유지는 의도된 규칙이다.

낚시가 오프라인에서 완료되더라도 기록은 재접속 시각이 아닌 서버가 정한 완료 시각을 사용한다. 지연된 완료 건을 한꺼번에 정산할 때는 완료 시각과 낚시 생성 순서로 처리해 전역 순번을 부여한다. 방해로 취소된 낚시는 포획 기록·도감·순위에 반영하지 않는다.

좌측 순위 한 행에 표시:

`순위 / 닉네임 / 최고 물고기 이미지 / 별 / 물고기 이름`

상위 20명을 스크롤로 표시하고 내 순위는 별도로 확인할 수 있게 한다. 포획 확정 후 실시간 갱신한다. 서버에 저장된 오프라인 사용자의 기록도 순위에 포함한다.

## 11. 물고기 공유

공유는 다른 플레이어에게 포획 사실을 보여 주는 기능으로 구현한다.

- 잡는 순간 캐릭터 위에 해당 물고기와 별이 잠깐 표시된다.
- 주변 플레이어도 같은 획득 연출을 본다.
- 최근 포획 피드는 닉네임·물고기 이미지·이름·별만 간단히 표시하고 최근 20건을 유지한다.
- 4~5성은 조금 더 눈에 띄게 표시하되 전원 화면을 가리는 팝업을 띄우지 않는다.
- 가방이나 도감 상세에서 “자랑하기”를 누르면 내 포획 기록을 다시 피드에 공유한다.
- 공유는 10초 간격으로 제한한다.
- 서버가 해당 포획 기록의 소유자를 검증한다.
- 판매한 물고기도 실제 포획 이력이 있으면 자랑할 수 있다.
- 다른 사용자를 클릭하면 이름과 최고 물고기 기록을 간단히 볼 수 있다.

## 12. 낚시 방해와 충전

낚시 중인 상대에게 접근하면 “방해” 버튼이 나타나고 Space 또는 클릭으로 발로 낚싯대를 찬다.

초기 방해 효과는 다음과 같이 고정한다.

**낚싯대를 발로 차면 상대의 진행 중인 낚시가 즉시 취소된다. 지연 효과로 바꾸지 않는다.**

- 이미 사용한 미끼는 반환하지 않는다.
- 예정됐던 물고기는 획득하지 못하고, 해당 낚시는 `CANCELLED_BY_SABOTAGE`로 확정한다.
- 취소된 낚시를 완료 Alarm이나 재접속 처리에서 다시 완료시키지 않는다.
- 낚싯대 장비 자체는 소유권을 유지한다. 발에 차여 튕겼다가 회수되는 연출이며 영구 분실·파손은 없다.

- 최초 3개, 최대 3개 충전.
- 성공한 방해에만 충전 1개 소비.
- 부족한 충전은 1시간마다 1개씩 회복.
- 오프라인 시간도 회복에 포함.
- 3개가 가득 차면 여분의 충전 시간을 쌓지 않음.
- 처음 3개에서 하나를 사용한 시각부터 다음 충전 시각을 계산.
- 이미 충전 중일 때 추가 사용해도 기존 충전 타이머를 초기화하지 않음.
- 예: 12:00 첫 사용, 12:20 두 번째 사용이면 첫 회복은 13:00.
- 이미 취소된 낚시는 다시 방해할 수 없음.
- 방해받은 플레이어는 60초 동안 추가 방해로부터 보호.
- 자기 자신, 낚시 중이 아닌 상대, 범위 밖 상대는 방해 불가.
- 본인이 낚시 중이거나 발차기·도주 모션 중이면 방해 불가.
- 상대는 기다리는 상태여야 하며, 이미 완료 시각을 지난 낚시는 먼저 정산.
- 여러 명이 동시에 같은 낚시를 방해해도 한 명만 성공하고 다른 요청에는 충전을 차감하지 않음.

연출:

`접근 → 상대를 바라보기 → 발차기 → 낚싯대 흔들림과 작은 충격 이미지 → 상대가 놀람 → 공격자가 짧게 달아남`

- 발차기는 몸 전체가 앞으로 기울고 다리가 뻗었다 돌아오는 실제 프레임 애니메이션으로 만든다.
- 발이 닿는 프레임에 낚싯대가 튕기고 찌와 줄이 거둬지며 낚시 모션이 끊어지는 연출을 맞춘다.
- 공격자는 상대 반대 방향의 유효한 땅으로 약 96픽셀, 약 0.6초 동안 달아난다.
- 이동 경로는 서버 충돌 검증을 거친다. 벽이나 물이 있으면 가능한 거리까지만 이동하고 관통·순간이동하지 않는다.
- 상대는 짧은 놀람 모션 뒤 의자에 앉은 기본 상태로 돌아간다. 낚시는 자동 재개하지 않고 다시 낚시를 눌러 새 미끼를 사용해야 한다.
- 서버 승인 결과를 받은 뒤 모두가 같은 방해 연출을 재생한다.
- 실제 판정과 소모를 스프라이트 프레임 이벤트에서 직접 실행하지 않는다.

충전 UI는 세 개의 작은 이미지 아이콘과 필요할 때만 다음 충전 시간을 표시한다. 충전은 서버 시각으로 계산한다.

## 13. 아트 방향: 모든 시각 자산을 이미지로 제작

목표는 밝고 편안하면서도 현대적인 캐주얼 게임이다. 둥글고 입체적인 형태, 부드러운 명암, 또렷한 실루엣, 절제된 광택을 사용한다.

필수 기준:

- 카메라: 고정 정사영, 약 40도 내려다보는 3/4 탑다운.
- 광원: 화면 왼쪽 위.
- 캐릭터: 약 2.7등신, 남녀 동일한 키와 머리 비율.
- 배경: 잔디·물·목재·돌·천의 재질 차이가 보일 것.
- UI: 두께가 느껴지는 이미지 버튼과 패널, 짧은 한국어 명칭.
- 모든 물고기·캐릭터·NPC·맵 소품·수면·낚싯대·미끼·의자·아이콘·버튼·패널·이펙트를 래스터 이미지로 제작.
- 글자와 숫자는 이미지에 굽지 않는다. 닉네임·가격·수량·순위·버튼 이름은 읽을 수 있는 실제 텍스트로 렌더링.
- HTML/CSS는 배치, 반응형, 입력, 텍스트, 접근성에 사용.
- Phaser는 이미지 배치·이동·스프라이트 재생·보간·크기·투명도·약한 회전을 담당.
- 낚싯줄도 얇은 이미지 스트립이나 상태별 이미지 프레임으로 표시하며 손·낚싯대 끝·찌의 위치를 연결.
- 별은 이미지 아이콘으로 표시하고 “3성” 같은 접근성 이름을 제공.

사용하지 않을 표현:

- 네온·형광 테두리, 강한 외곽 발광.
- 모든 패널에 반복되는 금색 고전 장식.
- 유리 카드와 웹 대시보드 같은 반복 박스.
- 과도한 영어 부제, 작은 설명문, 불필요한 sub text.
- 이모지로 대체한 물고기·장비.
- CSS 도형·SVG 아이콘·실시간 3D 모델로 완성 이미지를 대신하는 방식.
- 모든 소재에 같은 과도한 플라스틱 광택.
- 큰 이미지를 늘리거나 눌러 비율을 망가뜨리는 처리.

필수 상태 안내와 오류 메시지는 짧고 읽기 쉽게 제공한다. 불필요한 설명문을 줄인다는 이유로 미끼 부족·구매 조건·세션 오류까지 숨기지 않는다.

## 14. 캐릭터, 장비, 이펙트 제작 규격

남자·여자 각각 상하좌우 네 방향의 기준 이미지를 먼저 만든다. 모든 모션에서 얼굴·머리·의상·체형·조명을 유지한다.

각 캐릭터의 각 방향에 아래 모션을 준비한다.

| 모션 | 기본 프레임 수 | 용도 |
|---|---:|---|
| idle | 2 | 서 있는 호흡 |
| walk | 6 | 이동 |
| sit_down | 3 | 의자에 앉기 |
| seated_idle | 1 | 앉은 기본 자세 |
| cast | 5 | 낚싯줄 던지기 |
| fishing_wait | 2 | 입질 대기 |
| reel_in | 5 | 끌어올리기와 획득 |
| kick | 6 | 낚싯대 발로 차기 |
| run | 6 | 방해 후 달아나기 |
| startled | 3 | 방해받고 놀라기 |

기본 합계는 `39프레임 × 4방향 × 2캐릭터 = 312프레임`이다. 일어나기는 자연스러운 경우 sit_down 역재생을 사용한다. 어색한 구간에만 프레임을 추가하고 모든 모션을 무조건 같은 길이로 늘리지 않는다.

캐릭터와 장비는 다음과 같이 연결한다.

- 캐릭터 원본 프레임은 512×512 같은 일정한 캔버스를 사용.
- 지면 root는 예를 들어 정규화 좌표 `(0.5, 0.875)`로 기준을 정하고 모든 프레임에서 유지.
- 실제 이미지 크기와 캐릭터 몸 크기를 따로 검사. 프레임마다 자동 확대하지 않음.
- 몸체·접지 그림자·의자·낚싯대·획득 물고기는 레이어 분리.
- 의자도 네 방향 제작.
- 낚싯대 3종은 방향별 이미지와 필요한 휨·튕김·회수 이미지를 준비.
- 낚싯대마다 모든 캐릭터 프레임을 다시 그리지 않도록 손잡이 앵커와 앞뒤 레이어 순서를 정의.
- 각 프레임의 gripAnchor와 rodTipAnchor를 데이터로 기록.
- 캐릭터 손이 장비 앞에 와야 하는 프레임은 손/팔 가림 레이어 또는 동등한 합성 규칙을 준비.
- 낚싯대가 손에서 떨어지거나 뒷모습에서 몸을 관통하지 않게 검사.
- 옷과 소지손이 달라지는 경우 좌우를 단순 반전하지 않음.
- 자동 트리밍하면 원래 캔버스 크기와 오프셋을 아틀라스 메타데이터에 보존.

추가 이미지:

- 남녀 선택 화면용 캐릭터 전신과 작은 초상.
- 상점 NPC idle, 가판대 앞뒤 레이어.
- 의자 네 방향, 낚싯대 3종, 미끼 4종, 코인.
- 별 아이콘, 방해 충전, 가방, 상점, 의자, 잠금, 닫기, 행동 버튼.
- 버튼의 기본·눌림·비활성 이미지.
- 패널은 모서리가 늘어나지 않는 9-slice 규격.
- 물결·찌 흔들림·입질·물보라·획득 반짝임·발차기 충격의 짧은 스프라이트.
- 수면 애니메이션은 루프 이음새를 검사.
- 그림자도 이미지 에셋으로 준비.

물고기 이미지는 투명 배경의 1024×1024 원본을 기본 목표로 하고, 런타임에는 256~384픽셀 파생 이미지를 사용한다. 생성 도구의 출력 크기를 확인한 뒤 종횡비를 유지해 리사이즈·패딩한다. 꼬리와 지느러미를 자르지 않는다.

런타임 캐릭터 프레임은 표시 크기에 맞춰 약 192~256픽셀로 최적화하고 아틀라스는 우선 2048 단위로 나눈다. 프레임 사이 padding과 extrusion을 적용하고 고해상도 원본 전체를 GPU에 올리지 않는다.

## 15. 이미지 제작 절차와 파일 관리

사용 가능한 실제 이미지 생성·편집 도구와 기존 에셋을 먼저 확인한다.

도구가 있으면:

1. 캐릭터·물가·물고기·버튼이 함께 보이는 아트 기준 한 장을 만든다.
2. 남녀 네 방향 기준 이미지와 낚싯대·의자 기준을 만든다.
3. 걷기·앉기·낚시·발차기·도주 모션을 만든다.
4. 각 별의 대표 물고기 1종, 총 5종으로 스타일을 맞춘다.
5. 나머지 45종을 같은 기준으로 제작한다.
6. 환경과 UI·이펙트를 제작한다.
7. 아틀라스와 메타데이터를 만들고 실제 게임 크기로 검사한다.

기준 이미지가 유지되는지 확인하며 작업하고, 거대한 스프라이트 시트를 한 번 생성한 뒤 얼굴·손·발 위치 검수 없이 사용하지 않는다. 그림 안에 프레임 번호·격자선·파일명·체커보드 배경이 들어가면 수정한다.

도구가 없거나 일부 제작이 막히면:

- 코드와 에셋 연결 구조는 계속 구현한다.
- 필요한 각 파일의 생성 프롬프트·규격·경로·프레임 수를 작성한다.
- 개발용 임시 이미지의 상태를 manifest에 표시한다.
- 실제 이미지가 없는 항목을 “완료”로 집계하지 않는다.
- 최종 보고에서 준비된 에셋 수와 부족한 에셋을 구체적으로 구분한다.

에셋 구조:

```text
art/references/
art/source/
art/prompts/
art/manifest.json
public/assets/characters/
public/assets/fish/
public/assets/world/
public/assets/equipment/
public/assets/ui/
public/assets/fx/
```

manifest에는 최소한 ID, 종류, ready/placeholder/missing 상태, 원본 경로, 런타임 경로, 실제 크기, 프레임 키·시간, root·grip 앵커, 레이어 순서, loop 여부를 기록한다.

원본과 최적화된 배포 파일을 구분하고, 대형 원본을 앱 초기 로딩에 포함하지 않는다. 파일명은 안정적인 영문 ID를 사용한다.

### 물고기 생성 공통 프롬프트

```text

Consistent three-quarter side view facing right, upper-left lighting, rounded readable forms, soft material shading and restrained highlights.
```


캐릭터 모션 프롬프트에는 각 프레임의 자세·손 위치·발 위치를 추가하고 동일 기준 이미지를 참조한다. 머리 크기·얼굴·의상이 프레임마다 달라지면 수정한다.

## 16. 서버 판정과 실시간 동기화

### 권위와 원자 처리

클라이언트는 이동·행동 의도를 보내고, 서버는 결과를 결정한다.

서버가 소유할 값:

- 플레이어 ID와 세션 소유권.
- 유효 위치·충돌·행동 거리.
- 코인·보유 장비·미끼·물고기.
- 난수와 물고기 결과·등급.
- 낚시 시작·완료 시각.
- 방해 충전·보호 시각.
- 순위·전역 포획 순번.

클라이언트가 보내는 가격·코인 합계·등급·남은 시간·완성 좌표를 그대로 믿지 않는다. 메시지는 공통 스키마로 검증하고 크기·빈도 제한을 둔다. SQL은 바인딩 파라미터를 사용하고 닉네임을 HTML로 주입하지 않는다.

SQLite 트랜잭션으로 처리할 묶음:

- 계정 생성 + 이름 선점 + 최초 지급 + 세션 생성.
- 구입 비용 차감 + 아이템 지급.
- 물고기 판매 처리 + 코인 지급.
- 미끼 차감 + 낚시 결과와 일정 저장.
- 낚시 완료 처리 + 물고기 지급 + 도감/랭킹 갱신.
- 방해 충전 차감 + 대상 낚시 취소 + 보호 상태 변경.
- 무료 미끼의 자격 확인 + 지급.

SQLite DO의 transactionSync를 사용한다면 동기 콜백 안에 await나 네트워크 요청을 넣지 않는다. 저장이 확정된 뒤 성공 응답과 이벤트를 전송한다.

변경 명령에는 commandId를 사용한다. 같은 플레이어의 같은 명령 재전송에는 기존 결과를 반환하고, 낚시 지급은 castId, 판매는 보유 물고기 ID로 추가 중복 방지한다. 다른 commandId를 남발해도 “진행 중 낚시 하나”, “물고기 한 번만 판매” 같은 도메인 제약으로 막아야 한다.

### 이동

- 로컬 캐릭터는 입력 즉시 예측 이동하고 서버 보정.
- 입력 전송은 이동 중 약 10Hz를 시작점으로 삼고 실제 지연·부하로 조절.
- 서버는 입력 순번, 경과 시간, 속도, 충돌을 검증.
- 원격 캐릭터는 약 100ms 버퍼의 보간으로 부드럽게 표시.
- 이동 델타를 묶고, 동일한 정지 상태를 매 프레임 전송하지 않음.
- 움직임이 있을 때만 짧은 배치 타이머를 사용하고 유휴 상태에서는 정리.
- 전체 플레이어의 고해상도 상태를 매 입력마다 전원에게 재전송하지 않음.
- 고빈도 위치를 매 프레임 SQL에 저장하지 않음.
- 마지막 유효 위치·방향·연결 정보는 WebSocket attachment와 필요한 체크포인트로 복원 가능하게 관리.
- 연결 종료 시 낚시 중이 아닌 캐릭터는 정리한다. 진행 중 낚시의 캐릭터·의자·유효 위치는 완료 또는 취소까지 유지하며 상대가 방해할 수 있다.

### Hibernation과 시간 처리

메모리 변수나 setTimeout만으로 낚시·충전을 관리하지 않는다.

- Hibernation 뒤에는 메모리 상태가 사라질 수 있으므로 생성자에서 영속 상태와 소켓 attachment를 복원.
- WebSocket Hibernation API를 실제로 사용하고 계속 도는 서버 60fps 루프를 만들지 않음.
- 접속한 사용자가 많아 계속 이벤트가 발생하면 비용이 발생할 수 있음을 운영 문서에 반영.
- 진행 중 낚시는 SQLite에 완료 일정 저장.
- 한 DO의 Alarm 하나에 가장 가까운 완료 시각을 예약.
- Alarm에서 기한이 지난 낚시를 완료 시각 순으로 정산하고 다음 가장 가까운 시각으로 재예약.
- Alarm 중복 실행을 전제로 완료 처리는 멱등하게 구현.
- 취소된 낚시는 지급 대상에서 제외하고, 방해로 현재 가장 가까운 낚시가 취소되면 남은 일정의 가장 가까운 시각으로 Alarm을 다시 계산.
- 다른 요청 처리와 재접속 시에도 이미 완료 시각이 지난 낚시를 먼저 정산.
- 방해 충전은 사용자마다 타이머를 만들지 않고, 저장된 charges와 nextRechargeAt을 서버 현재 시각으로 계산.
- 재연결은 backoff를 사용하고 재연결 뒤 전체 스냅샷으로 정합성을 복구.

HTTP와 WebSocket은 같은 출처를 사용한다. 상태 변경 HTTP 요청과 WebSocket handshake의 Origin을 검증하되, 정상 동일 출처 GET에 Origin이 없다는 이유만으로 거절하지 않는다. 이미 열린 소켓도 세션이 만료·폐기되면 이후 명령을 거절하고 종료한다. 운영 세션 쿠키 설정과 개발용 localhost 처리를 구분한다.

## 17. 데이터와 코드 구조

최소 데이터 모델:

- players: ID, 이름, 정규화 이름, 캐릭터, 코인, 장착 장비, 최초 생성 시각.
- sessions: 토큰 해시, 플레이어, 만료 시각.
- player_rods / player_baits: 장비 소유·미끼 수량.
- fish_inventory: 실제 물고기별 인스턴스, 소유자, 포획 기록, 판매·잠금 상태.
- catches: 변하지 않는 포획 이력, 서버 완료 시각, 전역 순번.
- player_bestiary: 종별 최초 포획과 횟수.
- active_casts: 진행 상태, 결과, 시각, 장비 스냅샷, 의자 위치·방향, 취소 원인.
- sabotage_state: 충전, 다음 충전, 보호 만료.
- best_records: 최고 별과 대표 포획 이력.
- processed_commands: 플레이어별 명령 중복 처리 기록.
- schema_migrations: 적용된 스키마 버전.

활성 위치·온라인 명단과 영구 경제 데이터를 구분한다. 세션 토큰과 미공개 낚시 결과가 다른 플레이어의 스냅샷에 섞이지 않게 한다.

권장 구조:

```text
src/client/game/         월드·캐릭터·모션·입력·카메라
src/client/ui/           입장·HUD·순위·장비·상점·도감
src/client/network/      세션·WebSocket·스냅샷·재연결
src/server/              Worker 라우팅·GameWorldDO·저장소
src/shared/              타입·메시지 스키마·읽기 전용 카탈로그
src/config/              game-balance·map-data
art/                     원본·기준·프롬프트·매니페스트
public/assets/           최적화된 게임 이미지
scripts/                 에셋 검사·패킹·경제 시뮬레이션
tests/                   중요한 규칙·동시성·통합 검증
docs/                    구현 결정·아트 규칙·운영 안내
wrangler.jsonc
README.md
```

폴더 이름보다 책임 분리가 중요하다. 단일 React 컴포넌트에 네트워크·게임 루프·경제·전체 UI를 모두 넣지 않는다. 서버의 난수와 비밀 결과를 공유 카탈로그에 노출하지 않는다.

## 18. 구현 순서

단계를 나누어 진행하되 앞 단계의 시안만 만든 상태에서 전체 작업을 끝내지 않는다.

1. 저장소·도구 확인, 명세와 데이터 구조 정리, 프로젝트 실행 기반.
2. 아트 기준, 물고기 데이터 50종, 장비와 밸런스 설정.
3. 닉네임 세션, 단일 DO, 두 브라우저 실시간 입장·이동.
4. 맵·충돌·의자·한 회 낚시·서버 추첨·물고기 지급.
5. 판매·미끼·낚싯대 업그레이드·순위·도감.
6. 공유·방해·충전·모션 동기화.
7. 전체 이미지 연결·아틀라스·UI 마감.
8. 중요한 테스트·멀티플레이 검증·배포 설정·문서.

기본 미끼와 각 미끼 전략의 기대 수익·성장 시간을 간단한 시뮬레이션으로 확인하고, 결과를 문서에 기록한다. 2단계 약 10~20분, 3단계 약 45~90분은 초기 목표 범위일 뿐이며, 결과가 크게 다르면 수치를 조정하고 이유를 남긴다.

## 19. 반드시 검증할 완료 조건

### 실제 플레이

- 별도 브라우저 세션 두 개로 서로 다른 이름을 만들어 같은 월드에서 만남.
- 이동·앉기·낚시 방향·포획·방해 모션이 상대 화면에도 반영.
- 물속·나무·상점을 관통하지 않음.
- 상점 앞에서 구입·판매가 가능하고 범위 밖 요청은 거절.
- 물고기 50종과 남녀 네 방향 모션이 실제 파일로 연결.
- 모바일 앱 같은 캐주얼 완성도와 입체감이 실제 게임 화면에서 확인됨.
- 네온 테두리·과도한 부제·깨진 이미지·늘어진 패널이 없음.

### 규칙과 보존

- 동시 요청으로 같은 이름을 두 명이 만들 수 없음.
- 동일 이름만 입력해 다른 사용자의 캐릭터로 접속할 수 없음.
- 유효 세션으로 재접속하면 기존 장비·재화·기록을 복원.
- 1단계에서 4·5성, 2단계에서 5성의 추첨 확률이 정확히 0.
- 모든 유효한 장비·미끼·장소 조합에서 실효 확률 합계가 1.
- 50종은 중복 없는 ID와 이미지 연결을 가짐.
- 재전송·Alarm 중복·재접속으로 미끼와 물고기를 중복 차감/지급하지 않음.
- 중복 판매와 초과 구매로 코인·수량이 음수가 되지 않음.
- 대표 물고기를 팔아도 최고 기록 유지.
- 첫 5성 달성자가 이후 다른 5성 때문에 밀리지 않음.
- 서버 처리 지연과 재접속 순서로 순위가 뒤집히지 않음.
- Space를 계속 누르고 있어도 행동은 한 번만 실행.
- 한 낚시의 동시 방해는 한 번만 성공하며 해당 낚시는 즉시 취소.
- 방해로 취소된 낚시에는 물고기가 지급되지 않고 사용한 미끼도 반환되지 않음.
- 취소된 낚시의 Alarm이 나중에 실행되거나 재접속해도 물고기가 지급되지 않음.
- 이미 완료 시각을 지난 낚시에 늦게 도착한 방해는 거절하고 충전을 소비하지 않음.
- 연결을 끊어도 진행 중 캐릭터가 남아 방해할 수 있고 의자 자리가 겹치지 않음.
- 실패한 방해는 충전을 소비하지 않음.
- 충전이 오프라인에서도 시간당 1개씩, 최대 3개까지 회복.
- 추가 사용이 기존 회복 시각을 초기화하지 않음.
- 새로고침·장비 교체로 진행 중 물고기를 다시 추첨하지 않음.
- 코인·미끼·물고기가 모두 소진돼도 무료 보충으로 복귀 가능.

서버 경제·세션·랭킹·시간 경계의 테스트를 우선한다. 가능하면 Cloudflare Workers 테스트 환경과 실제 두 브라우저 통합 검증을 사용한다. 수행하지 않은 검증을 통과했다고 쓰지 않는다.

## 20. Cloudflare와 Git 배포 준비

실제 선택한 Vite/Cloudflare 구성에 맞춰 설정한다.

- wrangler.jsonc에 Worker 진입점, compatibility_date, Static Assets, Durable Object binding을 포함.
- 초기 migration에 `new_sqlite_classes: ["GameWorldDO"]` 등록.
- GameWorldDO 클래스를 Worker에서 올바르게 export.
- `/api/*`와 `/ws`는 SPA fallback보다 먼저 Worker에서 처리.
- HTML·게임 런타임 이미지 등은 정적 자산으로 제공.
- 선택한 빌드 결과 경로와 assets 경로를 일치시킴.
- 개발·테스트·운영 데이터 공간 분리.
- 환경 변수 예시와 .gitignore 작성.
- 실제 인증 정보·세션 토큰·API 키를 Git에 포함하지 않음.
- 의존성 잠금 파일 포함.
- README에 실제 작동하는 설치·개발·검사·빌드·로컬 Worker·배포 명령 작성.
- Git 저장소를 Workers Builds에 연결하는 방법과 production branch·build command·deploy command 작성.
- Cloudflare 대시보드의 Worker 이름과 Wrangler의 name을 맞추도록 안내.
- 저장소와 Cloudflare 연결 정보가 없더라도 로컬 구현·검증·배포 준비를 끝내고 필요한 연결 항목을 정확히 제시.

완료 보고에는 다음만 구체적으로 정리한다.

1. 구현한 기능과 실행 방법.
2. 실제 제작·연결된 이미지 수, 남은 이미지.
3. 수행한 테스트와 멀티플레이 확인 결과.
4. 알려진 제한과 미완료 항목.
5. Git 연결 및 Cloudflare 배포에 필요한 다음 단계.

기능이나 이미지를 만들지 않았는데 완료했다고 주장하지 말고, 임시 그래픽을 최종 아트로 제출하지 않는다.
