# 구현 구조

React 19 + TypeScript + Vite 8, Phaser 4.2.1. `src/config/balance.ts`의 수치는 초기 제안값이며 사람의 플레이테스트로 검증된 값이 아니다. 캐릭터는 후속 사용자 요청에 따라 원래 2.7등신보다 짧은 약 2등신으로 제작했다.

동일 출처 Worker가 `/api/*`, `/ws`를 먼저 라우팅하고 나머지는 Static Assets로 제공한다. 단일 `world-v1` GameWorldDO의 SQLite가 계정, 세션 해시, 경제, 포획 이력, 도감, 순위, 낚시 일정을 소유한다. D1/R2 중복 저장은 없다. 공개 카탈로그만 클라이언트와 공유한다. 결과 어종과 낚시 종료 시각은 서버의 active_casts에만 저장되며 완료 전에는 어떤 스냅샷에도 넣지 않는다.

도메인 변경은 동기 `transactionSync` 내부에서 처리한다. 실패 작업은 savepoint로 되돌리고 commandId의 성공/실패 결과를 30일 보존한다. 낚시는 활성 1건 UNIQUE 인덱스, 지급은 cast_id UNIQUE, 인벤토리는 판매 플래그로 추가 보호한다. 완료는 due_at/cast_order 순으로 처리하고 순위는 star DESC, caught_at ASC, sequence ASC이다. 같은 별 재포획과 판매는 최고 기록을 바꾸지 않는다.

Hibernation WebSocket API의 acceptWebSocket와 serializeAttachment를 사용한다. 입력 의도는 약 10Hz, 서버가 시간·속도·충돌을 검증하고 50ms 동안 변경된 플레이어만 배치 전송한다. 로컬은 예측 후 보정하고 원격은 100ms 버퍼 보간한다. 영구 60fps 서버 루프는 없다. 이동 중 짧은 전송 타이머만 존재한다. 고빈도 위치는 attachment에 저장하고 낚시/행동/접속 종료 시 SQLite에 체크포인트를 남긴다.

낚시는 SQLite 일정과 DO Alarm으로 유지한다. 재시작·Alarm 중복·오프라인 완료를 고려해 모든 핸들러가 완료 기한을 먼저 정산한다. 서버가 아닌 애니메이션 프레임으로 포획이나 발차기 판정을 바꾸지 않는다. 발차기는 횟수·충전 제한 없이 정면 가까운 상대에게 사용한다. 낚시 중이면 cast를 즉시 CANCELLED_BY_SABOTAGE로 확정하고 기존 낚싯대 놓침 모션을, 그 외에는 8방향 fallen 모션을 저장한다. 피해자의 모든 게임 명령과 이동은 1,500ms 동안 차단한다. SQLite에 방향과 시작 시간을 저장해 재접속으로 제한을 우회하지 못한다. 도주 경로는 동일 충돌 함수로 구한 유효 거리까지만 허용한다. 공격자는 기존 발차기 0.45초와 도주 0.6초를 재생한다. 자세한 타이밍과 자산은 kick.md를 참고한다.

세션은 32바이트 난수 토큰의 SHA-256만 저장하며 쿠키는 HttpOnly/SameSite=Lax/Path=/, HTTPS에서 Secure다. HTTP session 응답이 만료 시각과 쿠키를 함께 연장한다. WebSocket도 매 입력 세션을 확인하며 동일 계정 새 연결은 이전 연결을 4001로 닫는다. 클라이언트는 4001/4003에서 재시도를 중단한다. Origin 검사, Zod 스키마, 8KB 메시지 제한과 초당 입력 제한을 적용한다.

맵은 래스터 바닥·수면·물가·소품·캐릭터·장비·이펙트 레이어로 나뉜다. 바닥은 타일, 물가는 nine-slice이며 소품과 캐릭터는 접지 Y로 정렬한다. `?debug=1`은 실제 충돌 사각형과 물가 지점·수면 도달점을 표시한다. 물가 지점 간격은 40px이다. 플레이어 간에는 충돌하지 않으며 의자만 자리 검증을 한다.
